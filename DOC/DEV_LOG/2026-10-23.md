## 完成事项

### 1. 硬件贴装破案与 IMU PCB 背面极性反转修复
- **实测现象定位**：
  - 用户反馈设备物理朝向保持不变时，水平平放与竖直立起放置，地磁指向方向完全相反（相差整整 180°）。
- **根因分析**：
  - 结合用户提供的 PCB 背面正式图，确认 LSM6DSR（IMU 加速度计+陀螺仪）与 LIS2MDL（磁力计）实际贴装在 **PCB 的背面（Bottom Layer）**；
  - 面向屏幕正面看时，机身右手系为：$+X_{\text{dev}}$ 向右、$+Y_{\text{dev}}$ 向上（机身顶部）、$+Z_{\text{dev}}$ 垂直屏幕向外（朝向用户眼睛）；
  - 当设备正面屏幕朝天水平平放时，桌面支持力向上（$+Z_{\text{dev}}$），但对贴在背面的芯片而言，支持力作用于芯片背面，测得的芯片原始 $OUTZ_{\text{chip}}$ 实际为负（约 $-1000\text{ mg}$）；
  - 固件原配置 `#define IMU_AXIS_Z_SIGN 1` 未对背面贴装取反，导致归一化重力天顶向量在平放时算成 $\mathbf{u} = (0, 0, -1.0)$，**错误地指向了地心**；
  - 当设备长边竖立垂直放置时，支持力沿机身向上（$+Y_{\text{dev}}$），测得 $ay \approx +1000\text{ mg}$，重力天顶向量 $\mathbf{u} = (0, 1.0, 0)$ **正确指向了天顶**；
  - 倾角补偿正交东向向量 $\mathbf{E} = \mathbf{m} \times \mathbf{u}$ 因 $\mathbf{u}$ 符号反转，导致平放时正东被算成正西、正北被算成正南，航向角整整相差 180°！
- **闭环修复**：
  - 在 `main/config.h` 中修正 IMU 背面贴装右手系映射：
    `IMU_AXIS_X_SIGN = -1, IMU_AXIS_Y_SIGN = 1, IMU_AXIS_Z_SIGN = -1`；
  - 在 `main/sensors.c` 中修正平放静态校准（减去理论支持力 $+1000\text{ mg}$）。

### 2. 基于 IMU 重力矢量的全姿态平放与竖立自动感应自适应解算
- **视线前向自适应平滑模型**：
  - 平放时用户以机身顶部（$+Y_{\text{dev}}$）为前向目标；竖直立起（肖像模式）时机身顶部指向天顶（进入倾角奇异点），用户正前方的视线穿透屏幕背面（$-Z_{\text{dev}}$）；
  - 根据加速度计重力天顶向量分量构造连续加权动态前向向量：
    $$\mathbf{f}_{\text{ref}} = (0,\; uz,\; -uy)$$
    * 平放（$uz=1, uy=0$）对应 $\mathbf{f}_{\text{ref}} = (0, 1, 0)$（机身顶部，东向分量 $ey$，北向分量 $ny$）；
    * 竖立（$uz=0, uy=1$）对应 $\mathbf{f}_{\text{ref}} = (0, 0, -1)$（机身背面视线，东向分量 $-ez$，北向分量 $-nz$）；
    * 过渡过程严格满足 $\mathbf{f}_{\text{ref}} \cdot \mathbf{u} \equiv 0$，全空间连续平滑且无奇异点跳跃，航向在纯仰角抬起过程中保持 0.0000° 绝对一致与锁定。

### 3. 基于 GPS 定位经纬度的世界地磁模型（WMM）地磁偏角自动补偿
- **真北 vs 磁北闭环**：
  - 磁力计感应地球磁北极，GPS 轨迹与地图基于地理真北极，两者相差本地地磁偏角 $\delta$；
  - 在 `main/sensors.c` 中落地轻量级高精度地磁偏角查算函数 `sensors_calc_magnetic_declination`：
    * 中国及东亚主要区域（0°~55°N，70°~140°E）采用 WMM 双二次曲面经验模型，查算精度 $<0.5^\circ$；
    * 全球其他区域自动切换为大圆磁极偶极子测地模型；
  - `main/app_main.c` 在 GNSS 获得有效定位经纬度后，自动调用更新并将当前地磁偏角注入汇聚层；
  - 汇聚层输出真北航向 `heading_true_deg = heading_deg + declination_deg`。

### 4. UI 诊断页与码表页真北航向呈现
- **诊断页磁力计卡片**：

### 关键决策
- **决策**：NEO-M8N 的配置以“每次上电重新下发 + ACK 确认”为准，不依赖 BBR/Flash 保存。
  **理由**：原理图确认 `V_BCKP` 经 R16 0Ω 接 `VDD33`，无超级电容/纽扣电池，整机断电后 BBR 丢失；保存仅对 GNSS LDO 复位有效。
- **决策**：无源陶瓷天线 + `L2 47nH` 未焊，不开启 `VCC_RF`/`CFG-ANT` 天线供电，避免给无源天线加直流偏置。
- **决策**：`GPS+BDS` 仅启用 GPS+BeiDou 两个主星座，`ALL GNSS` 启用 GPS+GLONASS+BeiDou 三个主星座；SBAS/QZSS 默认不启用，降低 NAK 与通道占用风险。
- **决策**：18Hz 仅作为尝试值，NAK 自动回退 10Hz，避免设置页出现“改了不生效”的静默失败。

   - 采样：丢弃通道切换后前 2 次转换；采样 16 次；每次间隔 200µs；排序后取中间 50% 平均（抑制高阻分压尖峰）。

   - 预期：ADC 1915mV → 校准 2040mV → 电池 4.08V → 90%。
   - 饱和判断与百分比统一使用校准后电压。

### 关键决策
- **决策**：卫星页采用“固定列宽 + 顶部状态行 + 底部诊断行”，不再只显示裸数据行。
  **理由**：现场无 PC 时也能一眼判断 FIX/USED/HDOP、各系统卫星数、GSV 是否收到、数据是否过期。
- **决策**：电池校准放在 ADC 引脚电压域（gain/offset），不直接改分压比。
  **理由**：分压电阻是硬件属性；ADC 曲线/高阻源误差用软件增益修正更合理，后续换板只需重标 gain。

## 追加会话：NEO-M8N 的 CFG-PRT 无 ACK 与 PUBX,41 恢复

### 实机日志结论
- 9600 波特率探测成功：`locked @9600 after 410ms (attempt 1/3)`，说明 ESP32 RX ← 模块 TX 正常。
- 模块信息（`$GNTXT`）：
  - `HW UBX-M80xx 00080000`
  - `EXT CORE 2.01 (75350) Oct 29 2013`
  - `ROM BASE 2.01 (75331)`
  - `MOD NEO-M8N-0`
  - `PROTVER 15.00`
  - `GNSS OTP: GPS GLO, SEL: GPS GLO`
  - `ANTSUPERV=AC SD PDoS SR`
- `CFG-PRT -> UART1 115200 8N1` 连续两次超时，未收到 ACK/NAK → 模块没有接受 UBX 输入，而不是波特率探测失败。
- 原理图确认 `GPS_TX → GPIO17`、`GPS_RX → GPIO18`，硬件连线与固件一致；因此优先怀疑模块 UBX 输入协议被旧配置关闭（NMEA-only），或 TX 线在板上有虚焊。

### 修复
- 锁定 9600 后先发 `MON-VER` 做 UBX 探测：
  - 有响应：`UBX probe OK @9600` → 再发 `CFG-PRT` 升 115200；
  - 无响应：打印 `UBX probe no response @9600, try NMEA PUBX,41`，改用 NMEA `$PUBX,41,1,0003,0003,115200,0*CS` 启用 UBX+NMEA 输入并切 115200；
  - PUBX 后 `MON-VER` 成功：`UBX recovered via PUBX,41 @115200`，跳过 CFG-PRT 直接进入 CFG-RATE；
  - 仍失败：回退 9600 NMEA-only，不再反复重试。
- `CFG-PRT` 若在 UBX 探测成功后仍无 ACK，也会自动尝试一次 PUBX,41 兜底。
