## 完成事项

### 1. 硬件贴装破案与 IMU PCB 背面极性反转修复
- **实测现象定位**：
  - 用户反馈设备物理朝向保持不变时，水平平放与竖直立起放置，地磁指向方向完全相反（相差整整 180°）。
- **根因分析**：
  - 结合用户提供的 PCB 背面正式图，确认 LSM6DSR（IMU 加速度计+陀螺仪）与 LIS2MDL（磁力计）实际贴装在 **PCB 的背面（Bottom Layer）**；
  - 面向屏幕正面看时，机身右手系为：$+X_{\text{dev}}$ 向右、$+Y_{\text{dev}}$ 向上（机身顶部）、$+Z_{\text{dev}}$ 垂直屏幕向外（朝向用户眼睛）；
  - 当设备正面屏幕朝天水平平放时，桌面支持力向上（$+Z_{\text{dev}}$），但对贴在背面的芯片而言，支持力作用于芯片背面，测得的芯片原始 $OUTZ_{\text{chip}}$ 实际为负（约 $-1000\text{ mg}$）；
  - 固件原配置 `#define IMU_AXIS_Z_SIGN 1` 未对背面贴装取反，导致归一化重力天顶向量在平放时算成 $\mathbf{u} = (0, 0, -1.0)$，**错误地指向了地心**；
  - 当设备长边竖立垂直放置时，支持力沿机身向上（$+Y_{\text{dev}}$），测得 $ay \approx +1000\text{ mg}$，重力天顶向量 $\mathbf{u} = (0, 1.0, 0)$ **正确指向了天顶**；
  - 倾角补偿正交东向向量 $\mathbf{E} = \mathbf{m} \times \mathbf{u}$ 因 $\mathbf{u}$ 符号反转，导致平放时正东被算成正西、正北被算成正南，航向角整整相差 180°！
- **闭环修复**：
  - 在 `main/config.h` 中修正 IMU 背面贴装右手系映射：
    `IMU_AXIS_X_SIGN = -1, IMU_AXIS_Y_SIGN = 1, IMU_AXIS_Z_SIGN = -1`；
  - 在 `main/sensors.c` 中修正平放静态校准（减去理论支持力 $+1000\text{ mg}$）。

### 2. 基于 IMU 重力矢量的全姿态平放与竖立自动感应自适应解算
- **视线前向自适应平滑模型**：
  - 平放时用户以机身顶部（$+Y_{\text{dev}}$）为前向目标；竖直立起（肖像模式）时机身顶部指向天顶（进入倾角奇异点），用户正前方的视线穿透屏幕背面（$-Z_{\text{dev}}$）；
  - 根据加速度计重力天顶向量分量构造连续加权动态前向向量：
    $$\mathbf{f}_{\text{ref}} = (0,\; uz,\; -uy)$$
    * 平放（$uz=1, uy=0$）对应 $\mathbf{f}_{\text{ref}} = (0, 1, 0)$（机身顶部，东向分量 $ey$，北向分量 $ny$）；
    * 竖立（$uz=0, uy=1$）对应 $\mathbf{f}_{\text{ref}} = (0, 0, -1)$（机身背面视线，东向分量 $-ez$，北向分量 $-nz$）；
    * 过渡过程严格满足 $\mathbf{f}_{\text{ref}} \cdot \mathbf{u} \equiv 0$，全空间连续平滑且无奇异点跳跃，航向在纯仰角抬起过程中保持 0.0000° 绝对一致与锁定。

### 3. 基于 GPS 定位经纬度的世界地磁模型（WMM）地磁偏角自动补偿
- **真北 vs 磁北闭环**：
  - 磁力计感应地球磁北极，GPS 轨迹与地图基于地理真北极，两者相差本地地磁偏角 $\delta$；
  - 在 `main/sensors.c` 中落地轻量级高精度地磁偏角查算函数 `sensors_calc_magnetic_declination`：
    * 中国及东亚主要区域（0°~55°N，70°~140°E）采用 WMM 双二次曲面经验模型，查算精度 $<0.5^\circ$；
    * 全球其他区域自动切换为大圆磁极偶极子测地模型；
  - `main/app_main.c` 在 GNSS 获得有效定位经纬度后，自动调用更新并将当前地磁偏角注入汇聚层；
  - 汇聚层输出真北航向 `heading_true_deg = heading_deg + declination_deg`。

## 关键决策

1. **传感器坐标系严格遵循统一右手系与 PCB 贴装物理真实**：
   - 决策：明确面向屏幕正面的机身坐标系（X 右、Y 上、Z 前），根据 PCB 背面贴片图推导芯片内部各轴与机身轴的镜像与旋转映射，禁止通过在各个计算公式中人工硬凑负号掩盖硬件物理贴装事实。
2. **重力驱动视线自适应加权过渡模型**：
   - 决策：采用 $\mathbf{f}_{\text{ref}} = (0, uz, -uy)$ 作为视线参考向量，由重力向量动态驱动平放到竖立的无缝平滑连续过渡。
3. **基于 GPS 位置的透明地磁偏角补偿**：
   - 决策：无 GPS 定位时透明回退磁北，有 GPS 定位时自动平滑应用当地偏角输出真北，并在诊断页显示 `HDG(T)` 与偏角值 `(D:±x.x°)`。
4. **姿态融合不重复造轮子，直接引入成熟开源库**：
   - 决策：采用 x-io Technologies Fusion v1.3.3（MIT）原样 vendored 至 `components/fusion/`，适配层只做坐标/单位转换。
   - 理由：四元数 AHRS 涉及数值稳定性、磁/加计拒绝、启动收敛与超量程恢复，自研风险高；成熟库已有大量实际验证且代码量极小。

### 关键决策
- **决策**：NEO-M8N 的配置以“每次上电重新下发 + ACK 确认”为准，不依赖 BBR/Flash 保存。
  **理由**：原理图确认 `V_BCKP` 经 R16 0Ω 接 `VDD33`，无超级电容/纽扣电池，整机断电后 BBR 丢失；保存仅对 GNSS LDO 复位有效。
- **决策**：无源陶瓷天线 + `L2 47nH` 未焊，不开启 `VCC_RF`/`CFG-ANT` 天线供电，避免给无源天线加直流偏置。
- **决策**：`GPS+BDS` 仅启用 GPS+BeiDou 两个主星座，`ALL GNSS` 启用 GPS+GLONASS+BeiDou 三个主星座；SBAS/QZSS 默认不启用，降低 NAK 与通道占用风险。
- **决策**：18Hz 仅作为尝试值，NAK 自动回退 10Hz，避免设置页出现“改了不生效”的静默失败。

## 追加会话：卫星页对齐/状态增强、GNSS 初始化日志、电池 ADC 校准

### 会话

### 完成事项
1. **SAT INFO 页面重排**
   - 固定等宽列：`SYS ELE AZI CN0 U`，行格式 `G03 045 210 042*`，`*`=参与解算、`-`=未参与。
   - 顶部两行状态：
     - `FIX 3D  USED 8/21  HDOP 0.85`
     - `G8 R0 C13 E0 | GSV21 | 0.3s`
   - 10 行/页，超过自动 3s 翻页；底部显示 `GSV/NAVSAT` 计数与页码。
   - 无数据时显示 `NO SAT DATA CFG:<状态> GSV<n> NS<n>`，便于判断是 GSV 未收到还是解析失败。
2. **串口 GNSS 初始化/配置日志增强**
   - 初始化：`GNSS init ok: UART1 TX=17 RX=18, LDO EN=14, probe 9600/115200/38400, NMEA+UBX`。
   - 波特率探测：`attempt 1/3 @9600`、`no data, try attempt 2/3 @115200`、`locked @115200 after xxxms (attempt 2/3)`。
   - 配置：`CFG-PRT -> ...`、`CFG-RATE request: 10 Hz`、逐条 `CFG-MSG: NAV-PVT/NAV-SAT/GGA/RMC/GSA/GSV rate=...`、`CFG-GNSS request: GPS+BeiDou`、`CFG-NAV5`、`CFG-CFG save`，以及每条 ACK/NAK。
   - `MON-VER: SW=... HW=...`；首次检测到 GSV 系统时打印 `GSV system detected: GPS/BeiDou/GLONASS/...`。
   - 首次锁定后打印 8 条原始 NMEA 与最多 3 条校验失败样例。
   - 每 5s 打印 `SAT: used/view/GPS/GLO/BDS/GAL/QZSS/maxCN0/GSV/NAV-SAT`；每 10s 打印 `COUNTERS: GGA/RMC/GSA/GSV | NAV-PVT/NAV-SAT | crc | cfg_step`。
3. **电池 ADC 采样优化与校准**
   - 现象：日志 `BAT: 3.83V (ADC=1915mV raw=2147) 69%`，万用表实测 4.08V。
   - 采样：丢弃通道切换后前 2 次转换；采样 16 次；每次间隔 200µs；排序后取中间 50% 平均（抑制高阻分压尖峰）。
   - 校准：新增 `BAT_ADC_CAL_GAIN=1.0653f`、`BAT_ADC_CAL_OFFSET_MV=0`（单点：4.08V ↔ ADC 1.915V×2.0）。
   - 预期：ADC 1915mV → 校准 2040mV → 电池 4.08V → 90%。
   - 饱和判断与百分比统一使用校准后电压。

### 关键决策
- **决策**：卫星页采用“固定列宽 + 顶部状态行 + 底部诊断行”，不再只显示裸数据行。
  **理由**：现场无 PC 时也能一眼判断 FIX/USED/HDOP、各系统卫星数、GSV 是否收到、数据是否过期。
- **决策**：电池校准放在 ADC 引脚电压域（gain/offset），不直接改分压比。
  **理由**：分压电阻是硬件属性；ADC 曲线/高阻源误差用软件增益修正更合理，后续换板只需重标 gain。
- **决策**：保留单点校准默认值 1.0653；若后续有第二个万用表实测点，再补 offset 做两点校准。

## 追加会话：NEO-M8N 的 CFG-PRT 无 ACK 与 PUBX,41 恢复

### 实机日志结论
- 9600 波特率探测成功：`locked @9600 after 410ms (attempt 1/3)`，说明 ESP32 RX ← 模块 TX 正常。
- 模块信息（`$GNTXT`）：
  - `HW UBX-M80xx 00080000`
  - `EXT CORE 2.01 (75350) Oct 29 2013`
  - `ROM BASE 2.01 (75331)`
  - `MOD NEO-M8N-0`
  - `PROTVER 15.00`
  - `GNSS OTP: GPS GLO, SEL: GPS GLO`
  - `ANTSUPERV=AC SD PDoS SR`
- `CFG-PRT -> UART1 115200 8N1` 连续两次超时，未收到 ACK/NAK → 模块没有接受 UBX 输入，而不是波特率探测失败。
- 原理图确认 `GPS_TX → GPIO17`、`GPS_RX → GPIO18`，硬件连线与固件一致；因此优先怀疑模块 UBX 输入协议被旧配置关闭（NMEA-only），或 TX 线在板上有虚焊。

### 修复
- 锁定 9600 后先发 `MON-VER` 做 UBX 探测：
  - 有响应：`UBX probe OK @9600` → 再发 `CFG-PRT` 升 115200；
  - 无响应：打印 `UBX probe no response @9600, try NMEA PUBX,41`，改用 NMEA `$PUBX,41,1,0003,0003,115200,0*CS` 启用 UBX+NMEA 输入并切 115200；
  - PUBX 后 `MON-VER` 成功：`UBX recovered via PUBX,41 @115200`，跳过 CFG-PRT 直接进入 CFG-RATE；
  - 仍失败：回退 9600 NMEA-only，不再反复重试。
- `CFG-PRT` 若在 UBX 探测成功后仍无 ACK，也会自动尝试一次 PUBX,41 兜底。

## 追加会话：PUBX,41 已生效但 MON-VER 无响应，修正误回退

### 实机日志分析
- `$PUBX,41,1,0003,0003,115200,0*1C` 发出后，模块确实切换到了 115200：
  - 出现截断的 `$TXT,01,01,02,ANTSTATUS=OK*25`（原始 `$GNTXT...`，切换瞬间丢失 `$GN`）；
  - 9600 下 NMEA 计数停在 `GGA=2 RMC=3 GSA=4 GSV=4`，之后不再增加。
- 但 115200 下 `MON-VER` 仍无响应，旧逻辑误判为 PUBX 失败并回退 9600，导致模块在 115200、ESP 在 9600，后续完全收不到 NMEA。
- `SAT: used=0 view=0 ... GSV=4` 说明 GSV 句收到 4 条，但句内可见卫星数为 0；这不是页面解析问题，而是模块当前没有可见卫星（无源天线/室内/遮挡）。
- 电池校准已生效：`BAT: 4.08~4.09V (ADC=2042~2045mV) 90~91%`，与万用表 4.08V 一致。

### 修复
- PUBX,41 生效后：重发一次 PUBX,41 @115200，再走一次 `CFG-PRT`，然后 `MON-VER`；MON-VER/UBX 探测增加 1 次重试。
- 若 115200 下已收到已知 NMEA（包括截断的 `$TXT`），即使 `CFG-PRT/MON-VER` 失败也**保持 115200 NMEA-only**，不再回退 9600 丢数据。
- 只有完全没收到 115200 NMEA 时才回退 9600。

### 设置项是否会下发
- `GPS RATE` / `GNSS MODE` 修改后会调用 `gnss_set_update_rate()` / `gnss_set_gnss_mode()`，请求标志由 `gnss_task` 在 UBX 配置就绪后下发 `CFG-RATE` / `CFG-GNSS`。
- 当前若模块 UBX 输入/输出始终不可用，设置值会保存到 NVS，但**不会真正到达模块**；日志会显示 `CFG-PRT/MON-VER` 超时和 `fallback NMEA-only`。
- 若本次 PUBX/UBX 恢复成功，设置页修改后会在下一轮 `CFG-RATE/CFG-GNSS` 中下发并等待 ACK。

- 手册关键点：
  - `PUBX,41`（p136）可设置端口 `inProto/outProto` 与波特率，是 NMEA 侧打开 UBX 的入口；
  - `PUBX,40`（p138）只设置 NMEA 语句输出率；

2. **修正手册不符项**
   - `CFG-GNSS` flags：`0x01 → 0x00010001`；

3. **配置回读**

## 追加会话：SELFTEST 实机结果（UBX 全 NO，NMEA115200 通）

### 实机结果（commit 509cd52 / App 509cd52-dirty）
```text
SELFTEST UBX@9600=NO
SELFTEST PUBX@9600(0003)->UBX=NO
SELFTEST PUBX@9600(0007)->UBX=NO
SELFTEST PUBX@115200(0003)->UBX=NO
SELFTEST PUBX@115200(0007)->UBX=NO
SELFTEST SUMMARY: UBX9600=NO PUBX9600=NO UBX115200=NO PUBX115200=NO NMEA115200=YES -> use 115200
UBX unavailable, fallback to NMEA-only @115200
```

### 结论
- **UART 双向通路均正常**：
  - 模块 TX → ESP RX：9600/115200 NMEA 均可接收；
  - ESP TX → 模块 RX：PUBX,41 成功把模块从 9600 切到 115200（否则 NMEA115200 不会通）。
- **UBX 通道不可用**：
  - 9600 与 115200、0003 与 0007 协议掩码全部无 MON-VER 响应；
  - 说明不是波特率、不是 GPIO17/18 接线、也不是 PUBX 命令未收到。
- 可能原因：
  1. 模块 UBX 输入/输出在 Flash 配置中被禁用，且 PUBX,41 未真正改写协议掩码（仅改了波特率）；
  2. 模块为 NMEA-only 固件/兼容模块，`$GNTXT` 字符串可被模拟；
  3. 模块 UBX 通道硬件/固件异常。
- `cfg_step=FALLBACK`，`NAV-PVT=0`，因此 `CFG-RATE/MSG/GNSS/NAV5/CFG` 均未下发；设置页 `GPS RATE/GNSS MODE` 只写 NVS，未到达模块。
- 卫星 `view=0`，`GSV` 持续增长，NMEA 页面正常；问题在无源天线/视野，不是解析断流。

### 下一步建议
1. 再做一次“强制 UBX 输入”测试：
   `$PUBX,41,1,0001,0003,9600,0`（输入仅 UBX，输出 NMEA+UBX），再 MON-VER；
   若仍 NO，可判定 UBX 输入通道不可用。
2. 用 PC u-center 在 9600/115200 下读 MON-VER：
   - PC 也无响应 → 模块 UBX 被禁用/兼容模块，需换模块或重刷固件；
   - PC 有响应 → ESP 侧 UBX 发送/解析需继续查（但 PUBX 已证明 TX 通路正常）。
3. 室外/窗边复测卫星；当前 CN0 无数据，先排除天线与遮挡。
