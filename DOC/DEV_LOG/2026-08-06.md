## V0.1.2：MAG 偶发失效深度排查（对照 ST 官方驱动 + DS 手册）
### 日志破案（用户 bedda71 日志）
- T=35s/50s 现象「MAG 有完整数据但 RESULT: PARTIAL/FAIL」→ **diagnostics 双快照竞态 bug**：显示取快照 A，sensors_all_ready() 又取快照 B（50ms 内 MAG 瞬时失败即误报）
- 真实失败仅 T=2s/4s 两处（整帧 FAIL，温度也未读到）→ 瞬时总线级 NACK，设备未死（用户观察：FAIL 时手动读能读到数据）
### 根因与修复
1. **BDU 缺失**：CFG_REG_B 仅设 IF_ADD_INC(0x02)，未设 BDU(0x10)。DS p22 明确：异步读赶上数据更新会读到高低字节撕裂 → 补 0x12
2. **事务数减半**：磁 6B+温度 2B 合并为单次 8 字节连续读（0x68..0x6F 地址连续，IF_ADD_INC 自增）
3. **ST 官方驱动对照**：查 STATUS Zyxda → 连续读，无多余操作；其配置含 BDU（lis2mdl_block_data_update_set）
4. **失效容错**：sensors_update 继承上一帧完整状态；单通道偶发失败保留旧数据+计数，连续 SENSOR_FAIL_LIMIT=3 次才置 invalid；RESULT 与显示同快照；diag 显示 (stale) 标记
5. lis2mdl 重试/自恢复保留（总线复位 + 重初始化，宏参数化 LIS2MDL_READ_RETRY/LIS2MDL_FAIL_REINIT）

## V0.1.3：BMP388 寄存器地址错位大修 + 500kHz + 重要提醒
### 破案（用户日志 App version=bedda71 = V0.1.1 旧固件！V0.1.2 未实测）
- 用户确认手摸芯片：IMU 温度 27.7→29.9°C 正常变化，**LIS2MDL 恒 25.0°C、BMP388 恒 23.7°C** → 系统性死值
- **根因（BMP388）**：寄存器地址写错！我用的 PWR_CTRL=0x1C/CTRL_MEAS=0x1D，但 Bosch 权威定义是 **PWR_CTRL=0x1B / OSR=0x1C / ODR=0x1D**
  - 0x03 写进了 OSR（误设 osr_p=×8），0x46 写进了 ODR（误设 odr_sel）
  - **真正的 PWR_CTRL(0x1B) 从未被写 → 器件停在默认 sleep 模式（press_en=0, temp_en=0, mode=00）→ 永不测量 → 数据寄存器恒为复位值** → 795.5hPa/23.7°C 恒定
- **STATUS DRDY 掩码**：drdy_temp 是 bit6(0x40) 非 bit4(0x10)（Table 27）
- **补偿公式逐行对照 Bosch 整数版：完全一致** ✓（压力=厘Pa，÷10000→hPa 正确）
### 修复
1. bmp388.c：寄存器改 0x1B/0x1C/0x1D/0x1F；init 顺序 OSR→ODR→IIR→最后 PWR_CTRL=0x33 进 normal 模式；DRDY_TEMP=0x40
2. 配置：osr_p=×8、osr_t=×1、ODR=25Hz、IIR 系数 3（贴合"手持动态设备"推荐档）
3. I2C 降 500kHz（用户要求验证 MAG 稳定性）
4. ⚠️ 提醒用户：V0.1.2（BDU+单快照 RESULT+失效容错）从未被烧录验证，本次 V0.1.3 一并验证
